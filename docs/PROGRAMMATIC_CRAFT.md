# Programmatic craft: real end-to-end reference

## Goal

The repository must prove that a caller can create and machine a relief project without launching egui, using the same public domain and command APIs as the desktop app, CLI and MCP. This is a real integration path, not a mocked demonstration.

## Required scenario

The checked-in reference craft should produce a small engraved relief plaque from deterministic inputs:

- A project with explicit physical dimensions and material.
- A real 16-bit grayscale heightmap fixture or a relief generated by the production relief kernel.
- A real closed 2D boundary with at least one internal island (constructed as domain geometry or imported from a checked-in DXF/SVG fixture).
- A declared cutter from the actual tool model/database.
- A 3D finishing toolpath or a profile/pocket toolpath appropriate to the fixture.
- A stock-removal simulation, collision/gouge checks, and a postprocessed G-code file.

## Public API contract

The example must call the same typed application/session API that frontends use. Do not create a parallel helper that directly mutates internal document fields. Do not use fake toolpaths, mock geometry, mocked simulation summaries, canned G-code strings, or a fake session. File fixtures are real inputs; generated outputs must come from production algorithms.

The exact public Rust signatures will be taken from the implementation in this repository as it is built. Do not write illustrative signatures that have not been compiled. The first vertical slice must add the public API and example in the same change so the example is a compile-time client of the API.

## Execution stages and evidence

1. Create a document with explicit units, dimensions and stock material.
2. Import/build a heightfield and verify its bounds and min/max height.
3. Import/build a closed region and validate winding, closure, holes and bounds.
4. Add a real cutter and machining parameters.
5. Execute CAM through the engine command bus; assert path count, finite coordinates, valid feed/speed, safe Z and bounded depth.
6. Simulate the resulting toolpath against stock; assert nonzero material removal and no unexpected collision.
7. Run safety validation; unsafe results must block export.
8. Post-process with a selected dialect; parse/inspect output and assert required units, modal setup, tool/spindle commands, feed moves, safe retracts and program end.
9. Save the native project and all artifacts to a temporary output directory; reload the project and compare semantic state.

## Required artifacts

- `craft.gravita` (native project)
- `relief-preview.pgm` or another documented inspectable heightmap export
- `toolpath.json` (machine-independent path data)
- `simulation-report.json`
- `safety-report.json`
- `craft.nc` (postprocessed output)
- `manifest.json` containing input checksums, command IDs, parameters, crate versions, dialect and output checksums

## Acceptance

A single command such as `cargo run -p gravita-cli -- craft examples/plaque/manifest.toml --out target/craft` or `cargo xtask craft run --manifest examples/plaque/manifest.toml --out target/craft` must execute all stages and fail at the first invalid stage. The exact command is selected when the CLI exists; this example is not considered implemented until it compiles and its outputs are generated by real kernels.
